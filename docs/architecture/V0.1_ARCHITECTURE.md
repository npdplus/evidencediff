# EvidenceDiff V0.1 Architecture

**Status:** Accepted Pre-Implementation Architecture Baseline

## Architectural Goal

Keep V0.1 small while preserving boundaries that allow later CLI, CI, Viewer, provider adapters, and NPD PLUS integration without moving domain semantics into presentation or infrastructure layers.

## Logical Flow

```text
Local Inputs / Test Definition
          ↓
      apps/cli
          ↓
 packages/contracts
          ↓
 packages/core ─────→ Differences
          ↓
 packages/checks ───→ Check Results
          ↓
 core regression/verdict aggregation
          ↓
    Evidence model
          ↓
 packages/reporters
     ↙    ↓     ↘
 console JSON Markdown
```

## Package Responsibilities

### `packages/contracts`
Stable domain contracts: Run, Baseline, Candidate, Test Definition, Check, CheckResult, Difference, Regression, Improvement, Verdict, Evidence, metrics, versions.

### `packages/core`
Normalization, comparison orchestration, text/JSON semantics, regression/improvement classification, verdict aggregation, and structured result assembly. Pure domain behavior; no provider/UI/storage dependencies.

### `packages/checks`
Deterministic V0.1 checks and configuration validation. Check results are structured data.

### `packages/reporters`
Transforms canonical Evidence into console, JSON, and Markdown. Reporters must never recalculate product semantics.

### `apps/cli`
Loads local inputs/configuration, validates invocation, calls packages, writes requested reports, and maps valid outcomes to exit codes.

## Architectural Invariants

- Core is UI-independent;
- Core is provider-independent;
- Core is storage-independent;
- no mandatory network call for a V0.1 comparison;
- Evidence is canonical structured output;
- Difference and Regression are different domain concepts;
- machine verdict and human approval remain separate;
- configuration/runtime errors never masquerade as Candidate `FAIL`;
- V0.1 evaluation is deterministic.

## Data / Persistence

Local files only. No database is required. Test Definitions, captured outputs, fixtures, and reports are explicit developer-controlled files.

## Technology Direction

- TypeScript;
- Node.js LTS;
- pnpm workspace;
- Vitest;
- JSON Schema + Ajv where useful for data-contract validation;
- mature utility libraries for generic parsing/diff work when justified;
- no required React/Vite Viewer in V0.1.

## Anti-Goals

No microservices, queues, Kubernetes, mandatory Docker runtime, cloud database/authentication, provider SDKs in Core, speculative plugin framework, or distributed execution.
