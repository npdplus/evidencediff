# PromptDiff V0.1 Scope

**Status:** Accepted Product Baseline  
**Project:** NPD PLUS Labs / Experimental Open-source

## Goal

Prove that developers benefit from a focused local tool that compares an accepted Baseline with a Candidate AI output, runs deterministic checks, identifies regressions, and produces portable evidence before a change is accepted.

## Definition of Done for Product Scope

A developer can:

1. supply Baseline and Candidate local outputs;
2. compare plain text or JSON;
3. load a local Test Definition format `1`;
4. run deterministic checks with no provider account/API key;
5. distinguish Difference from Regression;
6. inspect optional supplied token/latency metadata;
7. receive `PASS`, `FAIL`, or `REVIEW`;
8. export Evidence format `1` as JSON and a human-readable Markdown report;
9. use the CLI completely offline after dependencies are installed.

## Required V0.1 Capabilities

- Baseline and Candidate are first-class domain concepts;
- plain-text difference detection;
- JSON structural difference detection including Added, Removed, Changed, and Type Changed;
- deterministic checks: JSON validity, required field, field type, exact value, contains, not-contains, regex, numeric range, allowed values, output length, token budget, latency budget;
- regression and improvement classification where Baseline/Candidate check results support it;
- portable versioned Evidence;
- CLI commands `compare` and `test`;
- explicit execution/configuration error handling.

## Verdict Rules

- Candidate required deterministic check failure -> `FAIL`;
- deterministic checks all pass and no explicit review is required -> `PASS`;
- no deterministic acceptance checks or an explicit human-review requirement -> `REVIEW`;
- operational/configuration failures are not product verdicts.

A Difference never becomes a Regression merely because content changed.

## Required Example Scenarios

1. structured JSON regression;
2. prompt-output regression;
3. captured Model A vs Model B comparison;
4. token/latency budget regression;
5. review-only comparison demonstrating that visual difference alone must not produce `PASS`.

## Explicit Non-Goals

No direct provider APIs, API-key storage, cloud accounts, hosted project storage, database dependency, prompt marketplace, agent orchestration, production tracing, observability dashboard, LLM-as-a-judge, semantic similarity release gate, team collaboration, or required Viewer.

## V0.2 Gate

V0.2 is considered only after V0.1 validates repeated real developer use. Candidates include reusable suites, batch cases, approved-baseline workflow, CI/GitHub integration, richer machine reports, and external run adapters. Provider execution remains a separate decision.

## Public Release Gate

V0.1 implementation/test completion does not automatically authorize public visibility. Security, documentation, examples, license/contribution, repository-history secret scan, and naming/searchability review must pass first.
